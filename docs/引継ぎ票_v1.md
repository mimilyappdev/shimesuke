# 引継ぎ票 v1（mimily-handoff）

MiteOrder → EasyReply → SchedulEX → RakuThrough で、1つの依頼を受け渡すための共通の形。
最初に使うのは SchedulEX → RakuThrough（2026-11-16）。

## 中身（JSON）

| 項目 | 型 | 説明 |
|---|---|---|
| fmt | 文字 | 必ず `mimily-handoff` |
| v | 数 | 版。今は `1`。形を変えたら上げる。受け取る側は知らない版を断り、「アプリを最新に」と案内する |
| src | 文字 | 送り元。`schedulex` など |
| id | 文字 | 送り元での案件ID（英数字・`-`・`_`、40字まで）。受け取る側は `src_id`（例 `schedulex_abc123`）を固有の名前にして二重登録を防ぐ |
| kind | 文字 | 種類（illustration / design / video / other） |
| amount | 整数 | **源泉を引く前の請求額（税込・円）** |
| currency | 文字 | v1 は `JPY` だけ |
| withholding | 真偽 | 源泉徴収あり |
| requestDate | 日付 or null | 依頼日 |
| salesDate | 日付 | **売上の日付＝納品日**（必須） |
| paidDate | 日付 or null | 入金日。本人が書く。空なら未入金（売掛） |
| paidAmount | 整数 or null | 入金額。本人が書く。あれば「請求額−入金額」を源泉として扱う |

送らないもの：依頼者名・案件名・メモ（リンクとコピー用コード）。
CSV には自分の記録用に「案件名」「依頼者名」「制作日数」も入る（RakuThrough は読まない）。

## 渡し方

1. リンク：`https://rakuthrough-app.netlify.app/#import=<JSONをbase64url>`
   - `#` より後ろはサーバーに送られない。
   - 受け取る側は、開いたらすぐ sessionStorage に保存してURLから消す → ログイン後に確認画面。
2. 引継ぎコード：`SCHEDULEX1.<JSONをbase64url>`（リンクが開けないときに貼り付ける予備）
3. CSV：UTF-8（BOM付き）、1行目が見出し。列：形式（`mimily-handoff/1`）, 案件ID, 種類, 案件名, 依頼者名, 金額, 源泉（あり/なし）, 依頼日, 納品日, 入金日, 入金額, 制作日数
   - Excel で式として動かないよう、`= + - @` で始まるセルの頭に `'` を付けている。

## 受け取る側（RakuThrough）の決めごと

（2026-11-16 RakuThrough担当セッションの確認を反映）
- 組み込み先は `C:\Users\iwill\rakuthrough-git\app\index.html`（Git管理・本番と同じ）。deploy-20261112 と rakuthrough/app は編集しない。
- 保存は ドキュメントID＝`schedulex_<id>`（setDoc）。読み込みが `{ id: d.id, ...d.data() }` なので、取引に `id` 項目は入れない。
- 上書きは、ルールで createdAt・source などを更新できないため、Rakutto! と同じく「削除してから作り直す」。
- 金額0は Firestore ルール（amount > 0）で書き込めないので、取り込む前に断る。SchedulEX側でも0円は送れない。
- 締め済み年度は `softLockCheck(fiscalYear)` を使う。
- 無料プランの月5件の上限（createdAt の月で数える）を、取り込みにも手入力と同じように掛ける。
- 前払いで年をまたぐ場合（例：2026年12月入金・2027年納品）は、確認画面とメモに「年をまたぐ前払い」と出す。

- 取り込む前に必ず確認画面を出す。送られた項目・送られていない項目・上書きなら差分を見せる。
- 同じ `schedulex_<id>` があれば「上書きしますか」。RakuThrough で入金済みにしたものが未入金に戻る場合は、その旨も出す。
- 売上の年度は納品日の年。締め済みの年度なら、Rakutto! と同じ確認を出す。
- 入金日が空 → 未入金（売掛・`pending`）。入金日が納品日以降 → 売掛で計上し、入金日で消し込み済み（`settled` + `settledAt`）。
- 入金日が納品日より前（前払い）→ 入金済みで取り込み、入金日はメモに残す。**会計上の扱いは RakuThrough 側で要確認。**
- 源泉の額は、入金額があれば差額、なければ「請求額×10.21%の切り捨て」で計算した「目安」として出す（RakuThroughの手入力は受取額から逆算するので向きが違う。100万円超の部分の20.42%はどちらも未対応）。確認画面で直せるようにする。
- ツールは税について「こうしてください」と言わない。一般的な説明だけにする。
- 部品と動作テスト：`docs/rakuthrough_schedulex_import.js`（Firestore への書き込みと画面は含まない）。
